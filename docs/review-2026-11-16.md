one idea built in several places, and stale references. Five Claude reviewers (one slice each)
and one Gemini pass (whole system) read the code at `f180a88`; the claims below that matter were

most important first, with the fix recommended.

## 1. The router, the checker and the judge see different boards

The biggest theme. Each reads the same board its own way, so the plan finds room the checker
then refuses, and the judge measures copper other than what was laid.

## 2. The router: what it still does not honour

- Rule areas with net conditions (`intersectsArea` + `NetName`) are not obstacles in the plan
  (`space.rs:482` takes only plain keepouts); a wire refused for one is barred from an unrelated
  gap (`wire/src/lib.rs:651-671`), matched by `format!("{:?}") == "Keepout"`.
- Pours say nothing about what may cross them (owner's decision today: each pour states it, as
  rule areas; fallback solid for an inner one-net plane). The fallback is in the tree, uncommitted.
- Length (`net_maximum`) rules are ignored by the plan. (`via_count (max 0)` was reported
  ignored; checked: the checker already refuses such a via when the plan tries one, and since
  2026-11-16 the search does not try.)
- Soft no-via areas (`via_avoid`) ignored; via spots are tested as net 0, so a rule naming a net
  drops spots for every net.
- No intent read (roles, Block.group, widths from current); no `route` crate, no `boardroom route`
  or `check` command, no Route mode; the plan is not saved (`route/<board>/plan.json`); stage
  pictures are SVG, not `scene`.
- `pcbench`, `rulebench`, `scoreboard` and `lab` speak only the frozen router's CLI, so only
  `prototype.py` judges the new router; `prototype.py` still needs the old router's path set.
- Recorded deviations from from-zero.md not yet written down: wire's repair rounds, one connection
  at a time with rip-up, frames and repeats unbuilt.

## 3. Packages are not yet a source boards can pin

- Nothing in Boardroom reads `manifest.toml`, circuits, `nets.json`, `support.json`, a package's
  `intent.json` or `layouts/*/layout.json`; only `ports.json`, `rules.json` claims, sources and
  the layout fixtures are read.
- No format for a block's layout rules (zones, rule areas with nets, planes per stackup); layouts
  are keyed by layer count.
- `kicad` cannot write zones, rule areas, groups or `.kicad_dru`.
- No optional-part field (it is in note text), no declined-change record, no version history,
  pins never checked against `packages/`.
- `Block.group` and many intent fields (`match_group`, `max_length`, `regions`, `domains`,
  `protection_paths`, ...) are written and read by nothing; metrics listed in intent are computed
  by Composer crates not brought in; `SCHEMA_VERSION` still 0.1 after schema changes.
- "Block" means four things (intent, KiCad group, recogniser name, layout name); roles are listed
  in three places (`intent::presets`, `examine::BuckRoles`, recogniser).
- Composer's claim check over the real `library/` and `packages/` no longer runs anywhere (its
  test was not brought in); `enforced_by` is free text naming `ccomp` checks; `packages/tools/`
  (11 tools incl. `library_quotes.py`) not brought in.
- Wrong data: `tlv62569` manifest says no layout (one exists); RP2350B footprint not shipped;
  layout footprint nicknames resolve only in the old project; six manifests name `~/Software/easy_pcb`.

## 4. The app against its specs

- `boardroom` has serve, open, add, remove, list, selection, link, push, snapshot; no `view`,
  `route`, `check`, `compose`, `new`, `doctor`.
- Compose and Route are iframes of the old apps (503 stubs locally, old Pages sites on Pages);
  no `/p/<id>/<mode>` routes, no `?window=1`; no root npm workspace.
- The server, snapshot and Pages workflow still run Composer's `ccomp` binary (Pages clones
  circuit-composer to build it): breaks when that repo is archived.
- `crates/project/src/gates.rs` is a second KiCad reader; its hash must match `gate_inputs.py`
  byte for byte and only easy2350 tests that.
- `layers.rs` lets any Foundation crate depend on another: nothing stops `kicad` linking the GPL
  `kicad-text`, `scene` gaining dependencies, or `render` depending on `server`.
- `npm run dev` is bare `vite` with no port: falls back to any free port (the machine forbids it).
- `status.json` v1 half built: `schema` unread, `needs_user[].job` dropped, template still the
  old shape (the static page shows "[object Object]" for v1).
- New board repos still get pcbview at `26ba32b` and `vendor/ultraroute`, so fixes in `view/`
  never reach them (accepted until step 7; say so).
- No `boardroom.toml`, no server jobs, selection over the server bus not `BroadcastChannel`
  (fix the spec), no live floorplanner in `wasm` (step 5).
