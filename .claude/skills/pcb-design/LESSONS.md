# Lessons

Corrections the user has had to give. Each is a rule. Read this at the start of every session. Add to it whenever the user corrects something.

Format: `- [area] What went wrong → what to do instead.`

- [schematic] Symbols placed on a grid and connected with global labels → group by function, arrange in signal-flow order, connect with wires within a block, labels only between blocks or sheets.
- [schematic] Inputs and outputs scattered around symbols → inputs on the left, outputs on the right, power on top, ground on the bottom; edit the symbol for this project if the library one fights this.
- [placement] ICs placed, then all passives dumped in a linear row → each passive placed with the pin it serves, in the order the datasheet layout guide implies.
- [routing] Manually routing by picking coordinates → pours/planes for power, short critical routes enabled by placement, autorouter for the rest.
- [power] Single via carrying a high-current net (e.g. motor bridge) → via arrays sized by calculation.
- [sync] Part numbers changed in the PCB or schematic without the other → schematic is the source of truth; run the sync check at every gate.
- [silkscreen] Designators under parts, chopped by vias, or overlapping → every designator visible, adjacent to its part, clear of vias, pads and other silk.
- [silkscreen] Connectors with no explanation → every connector labeled with function, polarity and rating (e.g. "+ −  12 V DC MAX").
- [datasheets] Parts chosen without reading the datasheet's fine print (e.g. bulk cap ripple current on BLDC controllers) → full datasheet audit per part, calculations recomputed by an independent reviewer.
- [pcbview] Later board variants tacked onto the viewer with less polish than the first → every variant registered in `pcbview.toml` and generated by the same tool.
- [datasheets] Audits marked parts UNVERIFIED because the maker's site blocked the download → fetch from LCSC (`jlc_parts.py fetch`), then try `wget -U Mozilla/5.0`; ask the user only after both fail.
- [sourcing] Took the first part-number match without checking lifecycle (WS2812B-2020: discontinued, 0 stock) → `jlc_parts.py show` every part; a part not `normal` with stock fails phase 1.
- [routing] Kept routing with Freerouting (DSN/SES, 16 settings variants, a maze finisher, ~50 min a route) when the user's own router, ultraroute, exists → route with ultraroute: pinned at `vendor/ultraroute`, built by `scripts/route.sh`, driven by `autoroute.py`. A router feature the board needs goes to the ultraroute project as a request (as pcbview changes do), never as a workaround script here.
- [nets] nets.csv skipped the nets KiCad names itself (`Net-(D1-A)`, `Net-(U4-Y)`), and nets_check only checked named ones, so 4 of easy2350's 65 nets went unclassified (found by circuit-composer) → every net joining two or more pins gets a row, under KiCad's name if the schematic gives it none; nets_check fails a missing one.
- [routing] A current-carrying net's class width is only the router's target: ultraroute necked VBUS to the board minimum (0.09 mm) at crowded pads, and DRC passed it → every net whose current needs more than the board minimum width (nets.csv, IPC-2221) gets that width in the `.kicad_dru` as a `track_width (min …)` rule, which KiCad DRC enforces and ultraroute honours. Plane nets (GND) are exempt: their tracks are pad stubs into the pour, each carrying one pad's current.
- [routing] easy2350 shipped with every track, via and footprint `(locked yes)`: a frozen Freerouting route, so after Composer moved a part its locked fan-out stayed behind, shorting pads, and Route's bare-board start (`--strip`) couldn't clear it → never lock routed copper; a board routes deterministically from a bare board with ultraroute (`--strip`, fixed seed and threads), and only parts the mechanics fix (connectors, holes, and what the floorplan spec marks fixed) stay locked.
- [routing] easy2350 kept a tracks keepout over L1's body and inside U1's pad ring from the locked-vendor-copper days; with the router laying that copper, the keepout blocked L1's own pads, VREG_LX stayed open and it was blamed on the router (and a repro made from the stripped finished board, without the routing-time keepouts, routed fine) → a keepout around a part's own pads must exempt that part's nets: draw a named rule area that restricts nothing and put the rule in the `.kicad_dru` (`A.intersectsArea('name') && A.NetName != '…'`, `disallow track via`), which ultraroute and KiCad DRC both enforce. A router repro is the router's real input (autoroute.py's copy, after the routing-time zones), never the finished board stripped.
- [routing] nets.csv length limits lived only in nets.csv and nets_check.py (track copper only), so autoroute.py's KiCad judge kept a seed with QSPI_SD0 at 27.5 of 25 mm and USB_D±_MCU through two vias → every length_limit goes in the `.kicad_dru` as `(constraint length (max …))` and every "no vias" row as `via_count (max 0)`, so KiCad DRC (which counts via barrels in the length) and the seed judge both fail it. ultraroute 770ef73 checks length rules after routing but does not route to them; that is asked of ultraroute.
- [routing] With no locked copper, easy2350's RP2350 regulator and 1V1 were left to the router, which laid 1V1 as 35 mm of 0.2 mm wire with a 9 mm FB loop and no ring under the chip (review-layout 2026-10-31 M3); the user chose the reference pours as zones → no locked copper does not mean no vendor geometry: copy the reference layout's power **zones** (relative to the anchor part, so they follow it) and let the router join them. Zones are kept by a bare-board route; tracks and vias are not.
- [setup] Started round-pendant from the bare `proj add` scaffold, running the skill from `~/.claude/skills` with no `scripts/`, no `vendor/` and no Boardroom entry, until the user pointed at Boardroom → a new board is a Boardroom project from the first step: vendor the skill into `.claude/skills/pcb-design/` (with `VENDORED_FROM`), take `scripts/` and the `vendor/pcbview` and `vendor/ultraroute` submodules from `skill_upstream`'s repo, write `design/status.json` as schema 1, and `boardroom add` the folder. SKILL.md's `scripts/doctor.sh`, `view.sh` and `route.sh` are the project's, not the skill's.
- [placement] On round-pendant, LED sites were packed up to the DRC minimum around USB-C's through-holes, and the user found it too close → a display's LEDs get visible breathing room round connector holes, not just the fab clearance; show the margin on a drawing of the LED side with the back-side connector overlaid.
- [placement] On round-pendant, every board-mounted USB-C left visible gaps in the LED pattern, and the user chose off-board USB with pads → when through-holes interrupt an LED display, offer off-board connectors and hole-free part variants (for example buttons without guide bosses) before trading margins or board size.
- [placement] On simple_earring, parts sat on the board's own art for several gates (Q3/R23 across the maker's name on the front; D2/Q2 across the repo URL on the back, whose arced letters also collided with each other), while silk_overlap warnings were filed under "gate 9" and ignored until the user noticed → art and identity text (names, URLs, logos) are placement obstacles: give each text's real outline to the spot scanner with the courtyards, and fail the placement gate on any part or text overlapping them. Check text-on-text collisions in generated arc/rotated text too. Don't defer a silk overlap involving art text to gate 9.
- [routing] On round-pendant, a subagent or script's remove command raised a danger prompt, and the user said to do it a safer way → no `rm -rf` or wildcard deletes in build scripts or agent work: make a new numbered folder or move the old one aside, and put that rule in every subagent brief.
- [routing] On round-pendant, zones built with pcbnew's ZONE() kept KiCad's default 0.5 mm clearance, which cut the GND plane to 20 pieces round through vias, left a 1V1 ring empty, and reported as 67 false plane opens over several trials → set clearance explicitly on every scripted zone, and after any fill check each zone's area and piece count, not just DRC.
- [routing] On round-pendant, 18 scan lines stayed in POWER at 0.2 mm for 7 routing trials because the intended 0.1 mm rule used a DRU condition the router warned it couldn't read → read the router's warnings before trusting a trial, and after the first route check actual track widths per net class against the plan.
- [routing] On round-pendant, `chips/rp2350.md` was followed literally and every routing trial was missing real U3 copper: the ±2.8 mm 3V3 band stops short of the pads (a subagent reports the vendor board joins them with short tracks), and "layer 2" for the LX cut landed on In2 when U3 on the back needs the layer next to B.Cu → check band-to-pin copper connectivity right after building U3's zones, read "layer 2" as the plane layer nearest the chip's own side, and add the regulator zones and PGND vias before the first routing trial. `chips/rp2350.md` itself still needs correcting. (fixed upstream 2026-11-06)
- [routing] On round-pendant, `pad_joints.py` passed boards where a track's end cap straddled a pad corner, because an end inside the pad counts as sound even when the copper chord is under the fab minimum: a subagent's unreviewed `necks.py` found 462 of 1123 joints under 0.09 mm on a board pad_joints flagged only 2 → don't treat a pad_joints pass as proof of joint width; measure the chord at the pad outline, or end tracks at least half a width inside the pad. `new_errors` also subtracts pre-route errors, so run a full DRC with zones refilled before quoting a route as clean.
- [routing] On round-pendant, `pad_joints.py` line 68 uses `pad.GetLayer()`, which returns F.Cu for a flipped pad (checked on U1), so back-side pads are tested against F.Cu copper: FAILs on them can be false and PASSes prove nothing → use `pad.IsOnLayer(pcbnew.B_Cu)`; corrected copy at round-pendant `scripts/crunch/placement/pad_joints_fixed.py`. The script itself still needs fixing upstream. Also, a route reaching 0 open can have got there by destroying fragile copper: on the same board foreign vias shredded U3's 1V1 ring from 6.1 to 1.5 mm² with DRC clean → after any complete route, check copper area and connected pieces of each critical zone, not just DRC. (fixed upstream 2026-11-06)
- [cost] On sensored-driver, the agent recommended paying JLC's filled-via charge (+$1.70 per board) as the quick fix for vias in pads; the user rejected it: a real per-board cost loses to making the board a little larger → on a cost-driven board, don't recommend a recurring fab charge to avoid layout work; price it against layout remedies, including a slightly larger outline, and treat layout as the default.
- [silkscreen] On round-pendant, `fp.Remove(g)` on a footprint's PCB_SHAPE segfaulted pcbnew in KiCad 9 → move the shape to a Fab layer, or use `fp.RemoveNative(g)` (reported by a Gemini agent, not checked here). Trust the copper pad, not a vendor 3D model's dot, for pin 1: EasyEDA's rotation was wrong for RP2350 and its XB9901A dot sits off pin 1.
- [routing] On round-pendant, a subagent's `necks.py` copied the `pad.GetLayer()` fault from `pad_joints.py`: it missed 8 real necks on back pads and reported 5 false ones → any tool that tests pads against tracks must use `pad.IsOnLayer`, not `GetLayer`, for flipped parts.
- [placement] On round-pendant, exposed pads were cut into copper tiles so other nets' vias could pass through (U3 3 vias; the rest of the board 47 more), and this was offered as an acceptable relaxation → an exposed pad is one solid ground pad: never route signals or other nets' vias through it, and never tile its copper around them. Solder needs the whole pad; its only vias are its own. If the pattern above a chip lands vias there, raise the conflict with the user before routing. Split solder paste into windows if needed, not the copper.
- [routing] On round-pendant, Variant D passed `kicad-cli pcb drc --severity-error` with 0 violations while carrying leftover ripped-up trace stubs, discontinuous cap-to-cap trace gaps, and 119 off-grid via grazes where a 0.10 mm trace stopped 0.14 mm from a 0.25 mm via's centre and touched only by endcap overlap: `.kicad_pro` had `min_connection = 0.0` and `via_dangling`, `copper_sliver`, `isolated_copper`, and `connection_width` set to `warning`, and KiCad's connectivity and `track_dangling` checks treat any same-net round-cap overlap > 0 nm as a valid join → set `min_connection` to the board minimum track width and set `track_dangling`, `via_dangling`, `copper_sliver`, `isolated_copper`, and `connection_width` to `error` in `.kicad_pro`, run `kicad-cli pcb drc --severity-all`, and audit routed copper topology so every track endpoint lands at a shared vertex, pad interior, or via centre, redundant partial-rip-up branches are pruned, and merged copper has no neck below the minimum track width.
- [routing] On round-pendant, each RP2350 IOVDD/DVDD pin-to-decap link was drawn as two butted 0.2 mm rectangular *zones* (`u3fix.py`), because zones survive autoroute's `--strip`; the escape-via planner skipped them (its keepout list named `DVDD`/`vendor`/`FB`, not `IOVDD`), five locked LED-cathode vias landed on them, the refill carved them into slivers and islands (C9's link kept 32% of its copper), and DRC/unconnected stayed 0 because the In5 3V3 plane still joined everything → a pin-to-capacitor link is a **track**: emit it as a locked pre-route (autoroute.py keeps locked copper and routes round it, and the via planners already avoid foreign tracks); zones are for areas, never for a thin strip. Audit every pre-placed zone after fill: fill below ~90% of its outline, or more than one island, is a defect even when DRC passes.
- [placement] On simple_earring, the LED matrix driver (variant C) was placed on the back directly under the front LED rings (between outer LEDs 8–10 and inner LED39), and so were its caps and ~25 other back parts. `scan_spot.py` checks only the part's own side, so it reported those spots legal, and the 4-layer routes then failed at the driver's pins (37–45 open). The user had to point out that the driver should dodge the LEDs → on a single-sided display, every through-via a front LED needs lands on the back too. Treat each LED's footprint plus its via room (~0.9 mm) as a keepout for back-side parts in the spot scan (`--keepout`). Put a matrix driver only where its whole courtyard is clear of every LED. Check the parts-vs-free-area budget before placing: on this board the back's free area off the LEDs (~203 mm²) was smaller than the movable parts' courtyards (~277 mm²), so not every part could clear the LEDs.
- [routing] On motionhexa-matrix Variant C, a two-pass flow (Pass 1 routes and locks every MCU/power net with the matrix pads off-net, Pass 2 routes the matrix) left 3 LED cathode links over the RP2354A open through seven retries, and the agent asked the user to move parts. The user asked instead to treat the LED block and the CPU as one fan-out: Pass 1's locked U4 escapes sat on the only via sites the LEDs above it had (all 8 had a site on the bare placement), and one pass with every net routed clean (0 open, 20 % fewer vias) with nothing moved → before proposing a placement change for opens in a congested block, check whether earlier locked copper took the block's via sites (compare via access on the bare placement against the pass-2 input), and route the block's nets together with the part under it, ideally in a single pass, rather than one after the other.
- [silkscreen] On round-pendant's 4-layer sunflower family, the generator left the front bare (it quoted a brief note) and printed only "BT1 + - 4.2V" by the battery, and the user had to ask for the main pendant's front web and for the buttons to say what they do → a variant inherits its parent family's finished silk, here the front seed web (lines between the LEDs) and back labels, unless the user drops it. Name every button by function on the silk ("PWR", "BOOT"), and give the battery its connector, polarity and type.
- [parts] On round-pendant, the user asked for a "JST" battery connector and picked "JST GH 1.25 mm" from a list; another reviewer then flagged that the 1.25 mm plugs on most small LiPo cells are friction-fit Molex PicoBlade clones ("micro JST 1.25", MX1.25), which don't mate with latching JST GH, so the board was re-routed twice → for any cable connector, choose by the plug on the part it mates with, not the series name sellers use: say which real series the cell or cable ships with (here PicoBlade 53261 or its clones), and offer the matching socket. Compare candidate courtyards before promising a site; PicoBlade (9.4 mm wide) is bigger than GH (7.0 mm).
- [publishing] On simple_earring, asked to publish the project page to GitHub Pages, the agent left the wear log (three minutes of accelerometer data from wearing the earring) off the public site as "personal activity data" without asking, and the user had to say it was no privacy risk and to include it → when publishing a project page, publish everything the local page links. If something looks private, ask before leaving it out rather than deciding for the user. Keep secrets and credentials out, as always.
- [power] On round-pendant's sunflower s2-110-usbc, the RP2350 layer-2 LX cutout was drawn as the bounding box of U3 pin 48 and L1's LX pad (+0.25 mm). The LX zone is a thin trace that runs ~4 mm down beside pins 46/47, so the box cleared 9.2 mm² of the In1 GND plane where 5.4 mm² was needed, including plane under VREG_AVDD/PGND, and the user spotted the "missing rectangle" in the viewer → build the cutout from the outline of the VREG_LX copper itself (zone ∪ LX pads, grown 0.25 mm), never a bounding box of separate pads; render the inner plane near the regulator and compare against the LX copper before the gate. The parallelogram generator had the same bounding-box code (fixed the same day).
- [parts] On bluebuzz ring5, the battery connector (PicoBlade, 1.0 A per contact) was audited assuming the motor rail's 1.25 A current-switch limit would only appear "for ms". The gate-6 reviewer pointed out that a current-limiting load switch (SY6280) *holds* its limit through a stall until thermal shutdown, which takes seconds. The user then chose a hardware fix: Rset raised so the limit's maximum plus the rest of the board stays under the contact rating → rate every series element (connector contacts, fuses, traces) for a stall held at the switch's **maximum** limit, plus the board's other continuous loads. A firmware duty promise is not a rating. Pick Rset from the datasheet law and its tolerance: the minimum must clear the loads running (and one start), the maximum must fit the weakest series part.
- [pcbview] round-pendant: new boards went into the published gh-pages copy of the front page (build/ghp/index.html) but not the project's own index.html, so the main page didn't show them until the user asked → a new board goes on the project's main page (index.html in the repo root) first; the published page is a copy of it, never edited on its own.
- [gates] On round-pendant, the sunflower s2-110-usbc variant was routed, DRC-clean and fab-exported, and the agent summarised it as "basically finished" with only fab-time checks left, though no variant of that family had any gate files or independent review. The user: "without gates it's not ready" → a variant's readiness is its gate files, not its DRC count or the fab files. Each variant gets its own `design/gates/<variant>/phaseN.md` from where it diverged. When asked what remains on a board, lead with any missing or unsigned gates, and never call a board ready to order without them.
- [pcbview] round-pendant: nine boards built in the viewer (all five parallelogram USB-C boards, the main Round Pendant F, the square-bezel BGA boards, s1-66 without vias in pads) had no main-page card, and an earlier "curate the front page" pass had dropped older variants, so the user never saw the USB-C boards. The user: "make sure every board we have is on the main page" → every board in `pcbview.toml` and every built viewer page gets a card on the main page, including probes and superseded variants (mark them as such; don't hide them). At each viewer rebuild, diff the board ids in `pcbview.toml` and `viewer/*.html` against the main page's cards and add any that are missing.
- [gates] On round-pendant, Gate 4 of sunflower s2-110-usbc-s3d sat at `awaiting_signoff` and the agent pointed the user at `design/gates/.../phase4.md`, the brief and a floorplan PNG by path. The user reviews on a phone and could open none of them: "if there's any review that's required I need a webpage that's accessible from the main page" → every sign-off or question waiting on the user gets a phone-readable web page linked from the main page: rendered HTML (never raw .md paths), its images inline, the decisions written in plain language with the options. On round-pendant `scripts/review_page.py` builds `design/review/` from every `awaiting_signoff` gate and `status.json` `needs_user`, puts a banner on index.html, and `--ghp build/ghp` publishes it; rerun it at every gate. When telling the user what to review, give the page's URL, not file paths.
- [power] On round-pendant's parallelogram p2-132-usb6 (U3 on B.Cu), the 1V1 ring zone was present and filled (8.6 mm², one piece), and Gates 6–7 passed it. But DVDD pins 6, 23 and 39 reached the ring only through 0.3/0.15 vias in the pads and 0.2 mm wires on In2.Cu/F.Cu, not the reference's four 0.6/0.25 spoke vias (N/S/W/E) with 0.6 mm wires. The W and E spokes weren't there at all. The user saw that the ring lacked the reference's links to the DVDD pins → after routing, list each DVDD pin's path to the ring and check it against `chips/rp2350.md`'s spoke table: via size, wire width, and that all four spokes are present. A filled ring with every pin connected doesn't satisfy "1V1 is never a thin wire". Make the spokes locked pre-routes at the reference sizes, mirrored for a back-side chip. When re-routing around them, also lock PGND's two plane vias: an `ultraroute --adopt` via pass dropped one of the pair as redundant, and only the independent review caught it. Count the vias in the `vendor GND` zone after every route.
